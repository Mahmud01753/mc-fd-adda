# 🛑🛑 সবার আগে পড়ুন — মালিকের কড়া সতর্কতা (২০২৬-১০-২৪) 🛑🛑

> আগে একটা AI মালিককে **না বলে** জিপ থেকে SQL, নোটবুক ও আপডেট ফাইল কেটে দিয়েছিল। এতে মালিকের বড় সমস্যা হয়েছে। **এটা আর কখনো হবে না।**

1. **কোনো আপডেটে** `sql/`, `private-notes/` (নোটবুক সহ সব নোট), `START-HERE.txt`, `READ-ME-FIRST-AI.txt`, আপডেট ফাইল — **জিপ থেকে কখনো ডিলিট/কাটা যাবে না**, মালিককে না বলে তো নয়ই।
2. **প্রতিটা আপডেট** `private-notes/CHANGES.txt`-এর একদম ওপরে লিখতে হবে (তারিখ · কী বদলেছে · কোন কোন ফাইল · SQL লাগল কিনা)।
3. **SQL লাগলে:** নতুন SQL **আলাদা ফাইল** হিসেবে চ্যাটে মালিককে দিন, একই ফাইল জিপের `sql/`-এও রাখুন, `sql/SQL-DONE.txt`-এ কিছু লিখবেন না (মালিক "ওকে" বললে তবেই ✅), আর এক লাইনে বলুন চালালে/না চালালে কী হবে।
4. **আপডেটের পর সবসময় ফুল জিপ ফেরত দিন** — সাইট + `sql/` + `private-notes/` + নোট/নিয়মের ফাইল, **সবকিছু সহ।** জিপ দেওয়ার আগে আগের জিপের ফাইল-তালিকা মিলিয়ে দেখুন; কিছু হারালে সাথে সাথে মালিককে বলুন।
5. SQL "✅ চালানো হয়েছে" লিখবেন শুধু মালিক নিশ্চিত করলে/চেক SQL-এ ✅ এলে।

বিস্তারিত নিয়ম নিচে ও `AI-RULES.txt`-এ।

## 📦 ফুল জিপের নিয়ম (মালিকের নির্দেশ, ২০২৬-১০-২৪)
- **ফুল জিপ এমন দিতে হবে যাতে সরাসরি আপলোড করলেই সাইট পাবলিশ হয়ে যায়** (Netlify বা যেকোনো হোস্টিংয়ে)। `index.html` জিপের root-এ থাকবে, সব ফাইলের লিংক ঠিক থাকবে।
- আপলোডের আগে কী কাটতে হবে/হবে না — সেটা মালিক নিজে জানেন। **শুধু এই একটা বিষয়ে** (আপলোডে sql/ ও private-notes/ কাটা/পাবলিক হোস্টিং) সহকারী আর সতর্কবার্তা বা মনে করানো দেবে না। **অন্য কোনো ঝুঁকি/সমস্যা/ভুল চোখে পড়লে সহকারী অবশ্যই মালিককে জানাবে।** বাকি সব নিয়ম আগের মতোই বহাল।


## 📦 SQL ফাইলের নিয়ম (মালিকের নির্দেশ, ২০২৬-১০-২৪)
- জিপের `sql/` ফোল্ডারে **প্রতিটা SQL আলাদা ফাইলে** থাকবে। **একাধিক SQL মিলিয়ে "ALL-IN-ONE" ফাইল জিপে কখনো রাখা যাবে না** (AI ও মালিকের বুঝতে সুবিধা)।
- মালিক "দুইটা/তিনটা/পাঁচটা একসাথে দাও" বললে — একসাথে করা কপি-পেস্ট ফাইল **শুধু চ্যাটে** দিন; জিপে আলাদা ফাইলগুলোই থাকবে।
- SQL ফাইলের নাম এমন হবে যাতে নাম দেখেই কাজ বোঝা যায় (যেমন SQL-1-CORE-..., RUN-NOW-LIMITS-...); "1-of-3"-এর মতো অর্থহীন নাম চলবে না। নাম বদলালে সব নোট মেলাতে হবে ও CHANGES.txt-এ পুরোনো→নতুন নাম লিখতে হবে।


# 🚨 FRIEND ADDA — AI/সহকারীর জন্য কড়া নিয়ম (আপডেটের আগে পুরোটা পড়ুন)

> মালিকের কড়া নির্দেশ। আগে একটি AI মালিককে না বলে প্রাইভেট নোট, SQL ও আপডেট ফাইল জিপ থেকে মুছে দিয়েছিল — **এটা আর কখনো হবে না।**
> বিস্তারিত পুরনো নিয়ম: `private-notes/AI-RULES.txt` (সেটাও মানতে হবে)।

## ❌ কখনো মুছবেন না — মালিককে না জানিয়ে
- `sql/` ফোল্ডার ও ভেতরের **সব** SQL ফাইল
- `private-notes/` ফোল্ডার ও ভেতরের **সব** নোট (`README.txt`, `CHANGES.txt`, `REVIEW-NOTES.txt`, `AI-RULES.txt`, `AI-RULES.md`, `site-sql-records/`)
- `START-HERE.txt`, `READ-ME-FIRST-AI.txt`, `sql/SQL-DONE.txt`
- আপডেট/নোটবুক/রেকর্ড টাইপের যেকোনো ফাইল
- "দরকারি না", "ঝুঁকিপূর্ণ", "সাইজ কমাতে হবে", "পাবলিশে লাগবে না" — **কোনো অজুহাতেই না।** মনে হলে আগে মালিককে জিজ্ঞেস করুন, অনুমতি পেলে তবেই।

## ✅ প্রতিটা আপডেটে করণীয়
1. `private-notes/CHANGES.txt`-এর **একদম ওপরে** নতুন এন্ট্রি: তারিখ · কী বদলেছে · কোন কোন ফাইল · SQL লাগল কিনা।
2. SQL লাগলে:
   - নতুন SQL **আলাদা ফাইল** হিসেবে চ্যাটে মালিককে দিন,
   - **একই ফাইল** জিপের `sql/` ফোল্ডারেও রাখুন,
   - `sql/SQL-DONE.txt`-এ "বাকি আছে: <ফাইলের নাম>" লিখুন (মালিক বললে তবেই "সম্পন্ন"),
   - এক লাইনে বলুন: চালালে কী হবে, না চালালে কী হবে।
3. আপডেটের পর **ফুল জিপ** ফেরত দিন — সাইটের ফাইল + `sql/` + `private-notes/` + `START-HERE.txt` + নিয়মের ফাইল — **সবকিছু সহ।**
4. জিপ দেওয়ার আগে ফাইল-তালিকা মিলিয়ে দেখুন: আগের জিপের কোনো ফাইল হারায়নি তো? কিছু হারালে সাথে সাথে মালিককে বলুন।

## ⚠ অন্যান্য
- যা বদলাতে বলা হয়নি তা বদলাবেন না; শুধু নির্দিষ্ট অংশ patch করুন।

## 📝 SQL চালানোর হিসাব — নাম ধরে ধরে (মালিকের কড়া নির্দেশ)
- `sql/SQL-DONE.txt`-এ **প্রতিটা SQL ফাইলের নাম আলাদা লাইনে** লিখতে হবে: "✅ <ফাইলের নাম> — চালানো হয়েছে" । "সব চালানো" / "আগেরগুলো" — এভাবে জেনেরিক লেখা চলবে না।

- মালিক "চালিয়েছি/চালানো আছে" বললে **সেই বার্তাতেই** ঐ ফাইলের লাইন "✅ চালানো হয়েছে" করুন (পরের বার্তার জন্য ফেলে রাখবেন না), তারপর আপডেট করা ফুল জিপ আবার দিন।
- `sql/RUN-ORDER.md`-এর অবস্থা কলামও একইভাবে মেলান।


## 🏷 প্রতিটা SQL ফাইলের মাথায় অবস্থা (মালিকের নির্দেশ)
