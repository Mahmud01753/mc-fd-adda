🛑 মালিকের সর্বশেষ নির্দেশ (২০২৬-১০-২৪) — নিচের "⏳ বাকি" লেখার নিয়মের ওপরে এটাই চলবে 🛑
- sql/SQL-DONE.txt ও sql/RUN-ORDER.md-এ কখনো "⏳ বাকি"/পেন্ডিং লেখা যাবে না। মালিক "ওকে/চালানো হয়েছে" বললে তবেই শুধু "✅ <ফাইল> — চালানো হয়েছে" লেখা হবে।
- sql/CHECK-ALL.sql, CHECK-EVERYTHING.sql, CHECK-SUMMARY-one-line-result.sql মালিকের নির্দেশে মুছে ফেলা হয়েছে (অপ্রয়োজনীয়); আর বানানো যাবে না।
- জিপের sql/-তে প্রতিটা SQL আলাদা ফাইলেই থাকবে; যত পেন্ডিং আছে সব একসাথে কপি-পেস্টের একটা ফাইল শুধু চ্যাটে দেওয়া হবে, জিপে নয়।

🛑🛑 সবার আগে পড়ুন — মালিকের কড়া সতর্কতা (২০২৬-১০-২৪) 🛑🛑

আগে একটা AI মালিককে **না বলে** জিপ থেকে SQL, নোটবুক ও আপডেট ফাইল কেটে দিয়েছিল। এতে মালিকের বড় সমস্যা হয়েছে। **এটা আর কখনো হবে না।**

1. **কোনো আপডেটে** `sql/`, `private-notes/` (নোটবুক সহ সব নোট), `START-HERE.txt`, `READ-ME-FIRST-AI.txt`, আপডেট ফাইল — **জিপ থেকে কখনো ডিলিট/কাটা যাবে না**, মালিককে না বলে তো নয়ই।
2. **প্রতিটা আপডেট** `private-notes/CHANGES.txt`-এর একদম ওপরে লিখতে হবে (তারিখ · কী বদলেছে · কোন কোন ফাইল · SQL লাগল কিনা)।
3. **SQL লাগলে:** নতুন SQL **আলাদা ফাইল** হিসেবে চ্যাটে মালিককে দিন, একই ফাইল জিপের `sql/`-এও রাখুন, `sql/SQL-DONE.txt`-এ কিছু লিখবেন না (মালিক "ওকে" বললে তবেই ✅), আর এক লাইনে বলুন চালালে/না চালালে কী হবে।
4. **আপডেটের পর সবসময় ফুল জিপ ফেরত দিন** — সাইট + `sql/` + `private-notes/` + নোট/নিয়মের ফাইল, **সবকিছু সহ।** জিপ দেওয়ার আগে আগের জিপের ফাইল-তালিকা মিলিয়ে দেখুন; কিছু হারালে সাথে সাথে মালিককে বলুন।
5. SQL "✅ চালানো হয়েছে" লিখবেন শুধু মালিক নিশ্চিত করলে/চেক SQL-এ ✅ এলে।

বিস্তারিত নিয়ম নিচে ও `AI-RULES.txt`-এ।

📦 ফুল জিপের নিয়ম (মালিকের নির্দেশ, ২০২৬-১০-২৪)
- ফুল জিপ এমন দিতে হবে যাতে সরাসরি আপলোড করলেই সাইট পাবলিশ হয়ে যায় (Netlify বা যেকোনো হোস্টিংয়ে)। `index.html` জিপের root-এ থাকবে, সব ফাইলের লিংক ঠিক থাকবে।
- আপলোডের আগে কী কাটতে হবে/হবে না — সেটা মালিক নিজে জানেন। শুধু এই একটা বিষয়ে (আপলোডে sql/ ও private-notes/ কাটা/পাবলিক হোস্টিং) সহকারী আর সতর্কবার্তা বা মনে করানো দেবে না। অন্য কোনো ঝুঁকি/সমস্যা/ভুল চোখে পড়লে সহকারী অবশ্যই মালিককে জানাবে। বাকি সব নিয়ম আগের মতোই বহাল।


📦 SQL ফাইলের নিয়ম (মালিকের নির্দেশ, ২০২৬-১০-২৪)
- জিপের `sql/` ফোল্ডারে **প্রতিটা SQL আলাদা ফাইলে** থাকবে। **একাধিক SQL মিলিয়ে "ALL-IN-ONE" ফাইল জিপে কখনো রাখা যাবে না** (AI ও মালিকের বুঝতে সুবিধা)।
- মালিক "দুইটা/তিনটা/পাঁচটা একসাথে দাও" বললে — একসাথে করা কপি-পেস্ট ফাইল **শুধু চ্যাটে** দিন; জিপে আলাদা ফাইলগুলোই থাকবে।
- SQL ফাইলের নাম এমন হবে যাতে নাম দেখেই কাজ বোঝা যায় (যেমন SQL-1-CORE-..., RUN-NOW-LIMITS-...); "1-of-3"-এর মতো অর্থহীন নাম চলবে না। নাম বদলালে সব নোট মেলাতে হবে ও CHANGES.txt-এ পুরোনো→নতুন নাম লিখতে হবে।


FRIEND ADDA — AI/সহকারীর জন্য নিয়ম (প্রতিবার আপডেটের আগে এটা পড়ুন)
=====================================================================

এই জিপ যে-ই (AI বা মানুষ) আপডেট করুক, নিচের নিয়ম মানতে হবে। মালিকের কড়া নির্দেশ।

১) কিছু কখনো মুছবেন না — মালিককে না জানিয়ে
   • sql/ ফোল্ডার, private-notes/ ফোল্ডার, START-HERE.txt, এই ফাইল (AI-RULES.txt) — জিপ থেকে কাটা/সরানো যাবে না।
   • ফাইল কমিয়ে সাইজ ছোট করার জন্য কিছু বাদ দেওয়া যাবে না। বাদ দিতে হলে আগে মালিকের কাছ থেকে স্পষ্ট অনুমতি নিতে হবে।

২) প্রতিটা আপডেট নোটে লিখতে হবে
   • private-notes/CHANGES.txt-এর একদম ওপরে নতুন এন্ট্রি বসান: তারিখ, কী বদলেছে, কোন কোন ফাইল, SQL লাগল কিনা।
   • বদলানো ফাইলের নাম আর কেন বদলেছে তা এক লাইনে লিখুন, যাতে পরের জন জিপ খুললেই বোঝে।

৩) SQL লাগলে
   • নতুন SQL আলাদা ফাইল হিসেবে মালিককে চ্যাটে দিন (চালানোর জন্য) — এবং একই ফাইল জিপের sql/ ফোল্ডারে রাখুন।
   • sql/SQL-DONE.txt-এ লিখুন: "বাকি আছে: <ফাইলের নাম>"। মালিক বললে তবেই "চালানো সম্পন্ন" লিখবেন।
   • SQL লাগলে কী কাজ করবে আর না চালালে কী হবে — এক লাইনে বলুন।
   • AI মালিকের Supabase-এ নিজে SQL চালাতে পারে না — এটা মালিককে বলে দিন।

৪) আপডেটের পর সবসময় ফুল জিপ ফেরত দিন
   • ফুল জিপে থাকবে: সাইটের ফাইল (root-এ) + sql/ + private-notes/ + START-HERE.txt + এই নিয়ম-ফাইল।
   • SQL লাগলে SQL আলাদা ফাইলও দিন, আবার ফুল জিপেও রাখুন।

৫) যা বদলাতে বলা হয়নি তা বদলাবেন না
   • শুধু যে অংশ বদলাতে বলা হয়েছে সেটা নির্দিষ্ট অংশ বদলে (patch) করুন। পুরো ফাইল নতুন করে লিখবেন না (chat.js ~১৪০ KB, লম্বা লাইন — ভুল ঢুকতে পারে)।
   • chat.js বদলালে index.html-এ chat.js?v=... সংখ্যা বাড়ান (stk2 → stk3), নইলে ব্রাউজার পুরনো কপি দেখায়।
   • config.js-এর Supabase URL/anon key বদলাবেন না। service_role/secret key কোথাও রাখবেন না।

৬) গোপনীয়তা
   • জিপে আসল আইপি, ইউজারের ব্যক্তিগত তথ্য, অ্যাডমিনের আসল ইমেইল রাখবেন না। (এখন আইপি = 0.0.0.0, ইমেইল = YOUR-ADMIN-EMAIL@example.com)
   • sql/ আর private-notes/ সাইটে পাবলিশ করা যাবে না — এ কথা প্রতিবার মালিককে মনে করিয়ে দিন।

৭) জিপের গঠন (সব হোস্টে চলার জন্য)
   • index.html অবশ্যই জিপের একদম root-এ। সাইটের সব লিংক রিলেটিভ (images/..., config.js)।
   • ভল্ট (vault.bin / admin-vault.js) মালিক সরিয়েছেন — ফেরত আনবেন না।
   • OG প্রিভিউ লিংক (index.html) এখন mc-fd-adda.previewship.net-এ লেখা — হোস্ট বদলালে সেটা বদলাতে হবে (মালিককে জিজ্ঞেস করুন)।


## 🏷 প্রতিটা SQL ফাইলের মাথায় অবস্থা (মালিকের নির্দেশ)
- sql/-এর প্রতিটা ফাইলের প্রথম লাইনে `-- ✅ STATUS: চালানো হয়েছে (...) | আবার চালানো যাবে কিনা` লেখা আছে — ফাইল খুললেই পরের AI বুঝবে কোনটা চালানো। নতুন SQL বানালে প্রথমে লাইন থাকবে না; মালিক "ওকে" বললে তবেই ওই লাইন বসবে (SQL-DONE.txt-এর সাথে)।


🛑 নিচের জায়গা খালি রাখার নিয়ম (মালিকের নির্দেশ, ২০২৬-১০-২৬) 🛑
